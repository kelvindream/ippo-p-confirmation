## 五、P1 停走判定（按方案 8.5 节，预注册口径）

效应量按方案 8.2 节：先在场景内对评估任务平均，按训练区组计算 `log(U_ref/U_new)`，对预指定场景族等权聚合，`1−exp(−mean_log_ratio)` 换回相对降低比例（正值 = 新方法更好）。

敏感性口径（全族 S0+H1+H2 等权）：IPPO+ 点估计 +0.0064%（2/3 区组），仍远低于 3%。

**P1 结论：未通过。** 效应量（≤0.1%）与门槛（3%）相差一个数量级以上，且 IPPO+ 未优于参数量对照。按原方案预注册规则，不进入正式 P2 候选筛选；用户于 2026-10-20 明确决定越级开展探索性 P2，须与正式阶段结论严格区分。

**证据边界**：本结论是发展阶段筛选判定，不构成“邻域信息普遍无效”的证明，也不构成对失败根因的因果证明；“argmax 塌缩 + 发展场景判别力不足”是当前证据最支持的解释假设（见第六节），尚需针对性检验。

## 六、下一步研判（2026-10-20）

### 诊断证据汇总

1. 实现与协议经 P0 全项验证，checkpoint/观测/守恒均无错误——失败不是工程 bug。
2. 九模型在 S0/H2 的确定性动作轨迹完全相同，H1 仅 4 种——策略概率差异（L1 达 0.12–0.18）无法转化为行为差异。
3. 三个发展场景在训练后策略下计划完成率均达 98.7–99.0%、无 teleport——所谓 oversaturated 场景 H2 实际未饱和，指标无足够 headroom。
4. 方法间 U 差异（±0.1%）远小于训练 seed 间噪声，即使存在真实小效应也不可分辨。

### 可选路线

- **A（建议）：动用 P1/P2 共享的唯一次重试额度，但采用“先导验证 → 预注册变更 → 才启动完整重跑”的分层执行**。
  - 变更内容仅限发展场景族（例如提高需求强度产生真实溢流/排队回溢，使不同策略的 argmax 动作分化、指标有下降空间）；方法、预算、评估协议、统计规则全部不变。
  - 第一步是**低成本先导检查**（不动用重试额度）：用 Fixed-Time、Max-Pressure 与现有 IPPO checkpoint 在候选场景上跑少量评估，预注册两条通过线——(i) 异质控制器间指标差异显著大于当前场景（有测量分辨率）；(ii) 不同 checkpoint 间动作轨迹哈希出现分化（argmax 不再塌缩）。
  - 先导通过 → 写变更备忘并启动 P1-v2 完整矩阵（消耗重试额度）；先导失败 → 按停走规则暂停本路线，转向问题重述，不再投入训练算力。
- **B（不建议）：强化 IPPO+ 的信息表示**（如按相位映射瓶颈信息）。这会在中途改变 B1 对照定义，破坏 C1 贡献的证据链，且方案禁止失败后加模块。
- **C（保底）：现在停止本技术路线**。理由是当前失败被测量分辨率问题混杂，无法区分“信息无价值”与“测不出来”；但在先导检查给出否定证据之前停下为时过早。

### 停止条件（预先声明）

- 先导检查两条通过线任一不满足 → 停止路线（不消耗重试额度）。
- P1-v2 矩阵重跑后仍未通过 8.5 节门槛 → 重试额度用尽，按方案第十章暂停该路线，另立方向需新证据与批准。

## 七、探索性 BR-IPPO / GR-GMAPPO-L 实现状态（2026-10-20）

- 已实现可运行代码和协议工具接入；这是**探索性分支**，不属于正式 P2 矩阵或正式候选，不改变 P1/P2 的预注册判定规则。未启动长训练。
- 两个方法均须由 `--ippo-init-checkpoint` 或 `GC_MAPPO_IPPO_INIT_CHECKPOINT` 显式提供匹配训练 seed 的 IPPO checkpoint；只复制 IPPO actor 权重，保留新建且独立训练的 local critic。未提供 checkpoint 时拒绝运行，不使用随机底座。
- BR-IPPO 冻结底座 actor，只优化消息编码、gate、bounded residual 和 local critic；GR-GMAPPO-L 用 clipped PPO 联合优化底座 actor、图消息/gate/residual 与 local critic。rollout、old log-prob 和 PPO 更新均基于同一合成 logits：local logits + sigmoid gate × tanh-bounded residual。
- 最小合理默认：residual limit=0.5 logits、gate bias=+1（初始 sigmoid gate 非饱和）、每个 rollout 更新 5 epochs、clip ratio=0.2；方案未规定残差与底座共同更新的完整细节，故采用联合 clipped PPO，不声称严格复现论文全文。
- 当前邻居消息是由现有 adjacency 计算的一跳邻居观测均值，再经小型编码器；属于探索版，不包含有向拓扑/物理下游方向特征，不能据此声称实现了方向性下游建模。
- 支持完整 agent state_dict 的 checkpoint 保存/载入及 runner resume_state 恢复。`paper_protocol.py` 将新源文件纳入 source hashes。需注意初始化 checkpoint 路径及其 seed 匹配由操作者负责，运行器不会自动发现/验证 seed 元数据。
- 该实现记录的是当前代码范围和技术限制，不构成方案规则变更或实验结果。

### 3. P2 判定

按方案 8.5，候选至少需要相对 IPPO+ 达到 3% 汇总 U 降低，且 3 个训练区组至少 2 个改善，同时满足服务率和关键场景退化门槛。

- BR-IPPO 的训练区组改善数为 0/3；GR-GMAPPO-L 为 1/3，均未达到至少 2/3。
- 完成率和需求守恒条件满足，但这只是必要的服务性筛选，不能抵消效率主指标未通过。
- **结论：本次 BR/GR 候选矩阵未通过 P2 候选筛选，停走。**

本次结果说明：在当前场景、当前一跳几何邻居均值表示、确定性 argmax 评估和 50 episodes 协同训练预算下，BR-IPPO 与 GR-GMAPPO-L 未产生可观测的交通效率收益；不能据此证明有界残差或图协同在更合适的压力场景、方向性瓶颈表示或不同评估设计下普遍无效。

此外，本次实际运行仅覆盖 BR-IPPO 和 GR-GMAPPO-L，未覆盖方案 P2 定义中的 B0、B3、B4，因此结果应称为“P2 候选矩阵未通过”，不应包装为完整 P2 机制矩阵或确认性证据。后续不应继续在当前矩阵上追加训练或反复调参；如继续研究，应先重新定义压力场景/方向性观测并形成新的预注册变更，或转向问题重述。


## DPG-MAPPO 探索性筛选矩阵（2026-10-21 至 2026-10-22）

## O2 评估决策对齐实验结果（2026-10-22）

### 1. 实验设计

- 目的：检验 GC-MAPPO 评估中的 hold-prior + 温度 0.30 是否为相对 IPPO 的不公平偏置来源。
- 方法：新增 GC_MAPPO_EVAL_PRIOR_SCALE 开关（默认 1.0 向后兼容，paper_protocol.py），对 gc_opt_v1 全部 12 个 checkpoint 以纯 argmax（scale=0）重评，评估 seed 1042/1043/1044 不变。
- 结果目录 results/gc_o2_reeval/；异常任务经单进程串行复测（gc_o2_serial）确认，隔离副本在 results/gc_o2_reeval_quarantine/。

### 2. 关键结果：执行 prior 是承重组件，不是评估偏置

- 12 任务中 3 个发生明显网格锁死（H2 base s44: U 3289.58 / tele 232；H2 ind s42: 2274.00 / tele 127；H1 ind s43: 1040.52 / tele 171），另有 H2 ind s44 严重退化（U 185.40、tele 4，主要由 eval seed 1042 驱动），完成率最低约 0.34。
- 串行日志记录了相同的崩坏/退化值，支持异常可复现；但隔离目录与主目录 JSON 为完全相同副本、未分别保存并发原件与串行复测原件，因此“逐位独立复现”的审计证据链不完整。
- 其余 8 任务无 prior 退化 +0.5% 至 +29.2%；即所有 12 个 checkpoint 移除 prior 后均变差。
- 结论：在当前 GC 训练/执行协议中，关闭 prior 会造成明显分布偏移并显著恶化性能；prior 是外部执行协议的承重组件。由于 checkpoint 不自包含 prior scale、温度、mask 等设置，且 O2 结果未保存当时 source hash，不应将其表述为模型自身强制保证的“安全契约”。

### 3. 由此暴露的新问题与下一步

- IPPO 纯 argmax 从不锁死，而 GC 策略离开 prior 即锁死：策略脆性存在于 GC 一侧。
- 缺失的对照：IPPO + 同一 hold-prior 评估。若 IPPO+prior 同样改善，则 prior 是通用执行改进而非 GC 专属贡献；若仅 GC 受益，才可主张交互效应。
- 该对照仅需对现有 P1 IPPO checkpoint 做评估（无需重训），协议需为 IPPO 评估路径添加与 GC 相同的 prior 构造与温度规则。
- 本轮 O2 不改变 O1 结论：独立 actor 为默认配置；GC(ind)+prior 与 IPPO 处于同一水平线。

### 4. 审计注记

- 分片日志中 SUMO 端口重试（每片 18-24 次）经验证无害：确定性逐位复现排除了连接串扰。
- 后续任何并发评估须报告端口重试计数并做抽查串行复测。

## IPPO+prior 对照评估结果（2026-10-23）

### 1. 实验设计

- 目的：初步判定把 GC 使用的原始压力先验公式（pressure z-score + hold-prior）事后注入独立训练的 IPPO 是否有改进价值。注意初版对照的有效 prior 系数为 1.0，而 GC actor 内部 action_prior_scale 为 2.25，因此初版只验证公式，不是强度完全匹配对照。
- 实现：agents/ippo.py select_actions 向后兼容扩展 action_priors/policy_temperature；paper_protocol.py 新增 _ippo_prior_actions（仅加 logits、不改观测）与 IPPO_EVAL_PRIOR_SCALE 开关（默认 0 关闭）。
- 对象：results/p1_dev_v1 的 h1/h2/s0_IPPO_seed{42,43,44} 共 9 个 50ep checkpoint，评估 seed 1042/1043/1044；结果 results/ippo_prior_eval/。
- 语义验证：零先验 argmax 与旧路径一致；强先验正确改变 argmax（单元测试通过）。

### 2. 结果：先验对 IPPO 无通用收益

| 场景族 | 相对 P1 IPPO 基线 | seed 改善 |
|---|---:|---:|
| H1 | −0.259% | 0/3 |
| H2 | +0.000%（U 逐位相同，先验未翻转任何动作） | 0/3 |
| S0 | +0.000%（同上） | 0/3 |

H1 的 +0.1~0.4% 轻微退化证明先验确实到达 logits 并偶尔翻转动作；H2/S0 的 U 逐位一致表明先验在强策略 logits 差距面前完全惰性。

### 3. 三方对照最终判定

| 比较 | 结果 | 含义 |
|---|---|---|
| IPPO+prior vs IPPO | ≈0（H1 −0.26%，H2/S0 =0） | 先验不是通用执行改进 |
| GC(ind)+prior vs IPPO | +0.302%（族，O1） | 同一水平线 |
| GC 无 prior | 3/12 明显锁死、1/12 严重退化，其余也全部变差 | GC 策略性能依赖当前外部 prior 执行协议 |

初步结论：scale=1.0 的事后 prior 注入对 IPPO 无稳定收益；但由于 GC 与 IPPO 的训练暴露、观测、semi-Markov 更新、soft-Q 以及有效 prior 系数均不相同，该结果不能单独支持“prior 对 IPPO 无效、仅与 GC 存在结构性交互”的因果结论。

### 4. 对论文主张的最终含义

- 当前场景族上不存在可测的 GC 专属机制收益（P1/P2/DPG/O1/O2/本对照六条证据一致）。
- 可选出路：(a) 重建真实饱和场景（预注册变更）创造机制空间后重验图/方向机制；(b) 论文转向"评估协议 + 压力先验-策略耦合的实证研究"叙事，GC-MAPPO 作为图协同 + 压力执行先验的耦合案例报告，与 IPPO 同水平线为诚实结论。
- 两者均需用户决策；在此之前不再新增候选算法训练。

## 上述结论独立核实与修正（2026-10-23）

### 1. 数据与计算核实

- P1 27/27、GC 优化 12/12、O2 12/12、IPPO+prior 9/9 文件齐全；核心评估数组长度均为 3。U 统一按每个训练 seed 内先平均 eval seeds，再对 H1/H2 等权平均 log(U_ref/U_new)，最后转换为 1−exp(−mean log ratio)。
- gc_base vs IPPO：H1 +0.1778%、H2 +0.0048%、族 +0.0913%，配对 seed 改善 1/3。
- gc_ind vs IPPO：H1 +0.4699%、H2 +0.1338%、族 +0.3020%，配对 seed 改善应为 **2/3**，不是此前记录的 3/3。
- gc_ind vs gc_base：H1 +0.2926%、H2 +0.1290%、族 +0.2109%，配对 seed 改善 3/3；方向一致但幅度远低于 +1% 门槛。
- planned completion rate、teleport 与需求守恒是不同字段：守恒通过不代表服务正常；O2 锁死任务可同时守恒通过且计划完成率低至约 34%。

### 2. IPPO prior 强度匹配复评

初版 IPPO+prior 使用 scale=1.0，而 GC actor 内部 action_prior_scale=2.25。为修正该不公平点，补跑同一 9 个 P1 IPPO checkpoint，使用 IPPO_EVAL_PRIOR_SCALE=2.25、评估温度 0.30；结果在 results/ippo_prior_eval_scale_2.25/。

| 场景族 | IPPO+prior(2.25) vs IPPO | seed 改善 |
|---|---:|---:|
| H1 | −0.1275% | 1/3 |
| H2 | −0.0446% | 0/3 |
| S0 | +0.0100% | 1/3 |
| 三场景族 | −0.0540% | 1/3 |

结论：在 scale=1.0 和 2.25 两种事后注入强度下，prior 对独立训练的 IPPO 均无稳定收益，且未引发 teleport。但这仍不是训练层面的公平消融：GC 在训练期即接触 pressure observation、prior、温度和 semi-Markov 更新，IPPO 只在评估时注入 prior；因此只能得出“事后 prior 注入不改善 IPPO”，不能得出 prior 与 GC 存在因果性交互。

### 3. 代码与审计核实

- GC 的原始 prior 由 pressure z-score/hold prior 构造后，在 actor 内再乘 action_prior_scale=2.25；初版 IPPO 未乘该内部比例，已补做 2.25 复评。
- IPPO select_actions 的 deterministic log-prob 原先未应用 policy_temperature，已修正为先缩放 logits 再统一构造分布；该修正不改变确定性 argmax 动作，但修正概率语义。
- GC checkpoint 并不自包含 prior scale、温度、mask、soft-Q 等完整执行配置；这些是外部协议设置。更准确表述是“GC 性能依赖当前外部执行协议”，而非模型自身保证的安全契约。
- O2 数据方向明确（12/12 移除 prior 后 U 变差），但其结果 JSON 未保存当时 source hash，且 quarantine 仅保留相同副本，独立复测证据链不完整；不应将“仅改变 prior、逐位独立复现”作为完全可审计事实。

### 4. 修正后的最终判断

1. 当前 GC(ind)+prior 与 IPPO 在 H1/H2 上处于同一水平线，点估计仅 +0.302%，不足以声称优越。
2. 独立 actor 相对共享 GC 有小幅一致改进（+0.211%、3/3），可作为工程配置，但不足以构成论文机制贡献。
3. 当前 GC 执行离开 prior 后明显脆弱；这是可靠的描述性结果，但脆性来源尚未通过训练层面的公平消融定位。
4. 压力 prior 不能作为已确认的独立贡献；IPPO 的事后注入在 scale 1.0/2.25 下均无稳定收益。
5. 若继续追求算法创新，下一项有效实验不是再做评估后注入，而是训练四格：IPPO 无/有 prior × GC 无/有 prior，并统一 prior 强度与执行规则；否则应重建真正拥堵场景后再测试图协同机制。

## AUD-01 勘误/复核记录：H2_IPPO seed45/seed46 评估文件逐位重复——判定为行为等价，非复制事故（2026-10-28）

- 背景：第 2 轮修订法证审计发现 `results/formal_four_grid_v1/H2_IPPO_seed45/` 与 `H2_IPPO_seed46/` 的 `evaluation_metrics.json` sha256 相同（5 集 U 向量逐位一致 [117.503297, 116.766187, 114.958483, 114.488010, 115.418016]），但 protocol_state 记录两次独立训练（train_seed 45/46，起止 06:47:40–08:04:41 vs 07:57:10–09:25:55），疑似 seed46 评估文件被 seed45 覆盖/复制（AUD-01）。
