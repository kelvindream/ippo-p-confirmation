## 一、总体决策与使用说明

### 1.1 拟定研究路线（待批准执行）

采用“**协议可信 → 信息增益成立 → 双候选最小实现 → 发展集筛选 → 单候选独立确认 → 外部有效性 → 投稿**”的路线。

1. 保留现有 IPPO 为核心性能基准，不再把“必须修好旧 GC-MAPPO”作为研究目标。
2. 同时保留 **BR-IPPO** 与 **GR-GMAPPO-L** 两个候选，但共用尽可能多的实现和实验协议，不扩展为多个大模型分支。
3. 两个候选的核心区别是：预训练 IPPO 局部 actor 在协同阶段**冻结**还是**继续联合训练**。
4. 首版均使用独立局部 critic、一跳邻域信息、门控有界策略残差；不同时加入全局 critic、新奖励、Q 执行、预测器或可变相位时长。
5. 先检验新增瓶颈信息是否确有价值；信息价值不成立，不进入大规模图残差训练。
6. 只在发展/验证数据上选择一个最终算法，然后冻结方法和统计计划。最终测试不能再次用于在 BR 与 GR 中择优。
7. 旧 GC-MAPPO 保留为历史方法对照；经典算法保留，但不能用数量众多的弱基线替代近期强基线。
8. 每个阶段必须有交付物、进入条件、通过条件和不通过后的明确动作，禁止失败后无限加模块、换指标或加种子。

### 1.2 名称与范围

- **BR-IPPO**：Bottleneck-aware Residual Independent PPO，工作名称，尚未实现。

- “-C”和“完整 GR-GMAPPO”暂不列为并行候选，也不预设为必须完成的论文创新点。

### 2.2 协议可信性优先于算法堆叠

P0 阶段必须完成以下验收，未通过不得开展候选性能筛选。

**A. 场景真的被加载。** 保存 SUMO 实际启动参数及解析后的 net、route、sumocfg、additional 文件列表与哈希；对两个明显不同的需求文件做固定控制器检查，核对计划车辆清单和真实载入文件，不能只看命令行显示。

**B. 车辆计数和时间戳可信。** SUMO 文档将到达接口定义为当前仿真步事件；TripInfo 默认在车辆到达时输出，未完成车辆需额外选项。[R8–R9] 用短小、车辆数可追踪的场景，将现有 tracker 与逐内部步收集、TripInfo/summary 输出交叉核对。验证跨10秒控制步及黄灯中间时刻的事件均未遗漏。计数必须逐车一致，时间差应在预先登记的内部仿真步误差内。

**C. 需求守恒。** 对每个场景建立计划车辆清单，截止评价终点，所有计划需求必须且只能归入一类：合规正常到达、到达但含被排除的异常事件、仍在网、暂时离网且等待重新插入、尚未首次插入、取消/永久异常移除。“尚未首次插入”仅包含仍等待首次插入的车辆，不包含已取消车辆；“取消/永久异常移除”额外区分是否曾经入网。无法归类即验收失败。Teleport另作跨状态标记，不将其累计次数或受影响车辆数重复加进守恒总数；含被排除teleport的到达归入异常到达，不算正常完成。P0须覆盖正在teleport和teleport后到达这两类边界案例。

**D. 动作和时序一致。** 区分“策略请求的动作”“实际执行的动作”“当前是否可决策”。训练和更新必须对同一有效决策及同一动作分布计算 log-prob；强制保持、黄灯、最小绿灯和动作掩码应在所有可比 PPO 方法中采用统一语义。若必须调整 IPPO runner，应同步调整同族对照并从头重训，不只修新算法。

**E. 终止语义一致。** 当前 done 来自时间上限。若将任务定义为有限时域，应明确终点目标及必要的剩余时间观测；若是持续控制的截断，应明确 bootstrap 与轨迹切片。不把“末步零价值”直接认定为错误，但不得在候选之间混用定义。

**F. 奖励与评价分离。** 首轮候选与 IPPO 使用同一经过核验的 reward，记录局部/全局混合比例。PressLight 等保留论文规定的原生训练目标时，应披露差异；正式性能用统一交通指标，不能比较不同 reward 的数值大小。

**G. 工程可重复。** checkpoint 往返后相同输入输出一致；同 seed 重跑的环境轨迹在已声明的确定性容差内一致；优化器覆盖全部应训练参数；冻结参数不变；配置不兼容的 resume 明确拒绝；失败目录只归档不删除。

**H. 基线真实。** Double DQN 的 online argmax/target 评价、Dueling 分解、REINFORCE 的 on-policy MC、GAE AC 的优化器与优势计算逐项验收。保留参数共享说明，不能因名称简化而隐去共享结构。

## 四、两候选的最小、可比定义

### 4.1 共用底座与观测

每个路口保留完整独立局部 actor 和 critic，而非只保留独立输出 head。共享协同模块可作为设计，但其参数共享方式必须登记并在控制组中匹配。

局部输入为核验后的基线状态。新增信息仅来自真实当前观测或允许的历史观测，不读取未来车辆出发、未来路径或未来真实到达。

首版邻域信息建议限定为：

- 与本路口候选相位可服务流向对应的下游车道占用/剩余存储比例；
- 直接相邻路口当前相位及当前可观测排队/密度；
- 道路连通方向、长度、车道数等静态属性；
- 消息有效性和消息年龄，避免将失联填零误认作道路畅通。

剩余存储比例可由既定车道容量近似与当前车辆数构造，例如 `max(0, 1 - occupancy_ratio)`；这只是可解释代理量，不直接称为精确可接纳流率或测得容量。首版不新增预测模型、真实转向意图获取或未经说明的全车联网信息。

**建模要求：** 道路邻接必须与车流方向一致；下游瓶颈信息要映射到可服务该方向的相位，而不是把所有邻居无区分平均。第一版使用一跳、固定合法邻域，避免两跳/全网与多头搜索同时展开。

### 4.2 共同策略形式

对路口 i：

\[
 z_i(a)=z_i^{base}(o_i,a)+\delta_i(a),\qquad
 \delta_i(a)=c\,g_i(o_i,m_i)\tanh h_i(o_i,m_i,a),
\]
\[
 \pi_i(a\mid o_i,m_i)=\operatorname{softmax}(z_i)_a.
\]

其中 `m_i` 为一跳图聚合信息，`g_i` 为 [0,1] 内的标量门控，`c>0` 为在发展集选择并锁定的 logit 修正上限。合法动作掩码在采样和更新时一致应用；若温度不是1，应对照统一并在幅度解释中计入温度。

首版初始化：局部 actor 来自同一 IPPO checkpoint；残差最后一层权重和偏置置零；gate 使用可训练的非饱和初始化，不使用使整个残差分支永久无梯度的硬零门。预期第一步可能只有残差输出层获得梯度，应通过后续多步检查 gate/encoder 确实开始学习。

### 4.3 BR-IPPO：冻结底座候选

- 阶段一：按公共预算训练 IPPO，形成对应训练 seed 的基础 checkpoint。
- 阶段二：冻结局部 actor，只训练图消息、gate、残差输出；局部 critic 继续适配新策略。
- PPO 的实际采样、缓存 old log-prob、更新 new log-prob 都来自合成策略，不使用单独底座概率替代。
- 底座保留独立保存能力；显式缺失全部邻域信息时，可以按预定义规则关闭残差。
- 优点是把新增更新限制在修正分支；这是结构性约束，不是性能保证。
- 风险是底座已形成不易修正的行为模式，或有限幅度不足以纠正关键错误。

### 4.4 GR-GMAPPO-L：联合训练候选

- 与 BR 使用相同预训练 checkpoint、协同结构、特征、critic、数据预算和更新频率。
- 协同阶段同时训练局部 actor、图模块、gate、残差；局部 critic 同样继续训练。
- 不通过加入全局 critic 或额外奖励来制造与 BR 的差异。
- 主要研究“局部适应性”与“保留底座能力”的折中。
- 关闭残差只得到当前已更新的局部 actor，不能宣称回退至原始 IPPO。
- 从头训练版本只作后续初始化消融，不混入首轮冻结/联合训练的主对照。

### 4.5 可以证明什么，不能证明什么

在相同状态、相同合法动作集合、温度为1，且各动作修正满足 `|δ(a)|≤c` 时，令 `p=softmax(z)`、`q=softmax(z+δ)`，则：

\[
\frac{q(a)}{p(a)}=\frac{e^{\delta(a)}}{\sum_b p(b)e^{\delta(b)}}\in[e^{-2c},e^{2c}],
\quad D_{KL}(q\|p)\le 2c.
\]

这是由上下界直接得到的宽松分布扰动界，不是本项目独有的理论创新，也不推出交通回报非劣、训练收敛或全局稳定。若使用温度 τ，界中的 c 应替换为 c/τ。

另外，即使概率分布差异较小，两个动作的 logit 很接近时，确定性 argmax 仍可能翻转。因此必须记录实际动作改动率、相位切换与闭环交通效果，不能只看 KL。冻结/关闭残差也不能撤销先前动作已经改变的交通状态。

### 4.6 首版明确不做

不加集中全局 critic，不加 action-conditioned Q 和 soft-Q 执行，不加新的压力奖励，不加预测器，不加多尺度图，不改变相位持续时间，不将 critic 优势、actor 优势和执行规则变化一起归因于残差。

若未来需要上述任一项，必须另写变更理由、控制组与预算影响，不能直接覆盖锁定版本。

## 五、公平对照与算法清单

### 5.1 同机制控制组

| 代号 | 方法 | 解决的问题 |
|---|---|---|
| B0 | IPPO，完整公共预算继续训练 | 新算法是否真正超过强局部控制 |
| B1 | IPPO+，直接拼接相同邻域/瓶颈信息 | 改进来自新信息还是残差结构 |
| B2 | IPPO-Cap，保留局部输入并增加近似匹配参数量 | 改进是否仅来自容量增加 |
| B3 | 相同图与信息的有界残差，gate固定为1 | 门控是否必要 |
| B4 | 相同信息的非图聚合/固定顺序拼接残差 | 图聚合是否必要 |
| A | BR-IPPO | 冻结主干的选择性修正 |
| B | GR-GMAPPO-L | 联合训练的选择性修正 |

B3应与最终获胜候选匹配冻结方式；若最终候选是 BR，不拿联合训练的无门控版本当唯一门控消融。B4在固定拓扑上进行时要保留相同邻居集合、方向与消息有效性。参数量不可能完全相等时报告实数与差异，不虚称完全等容量。

B1若输入维数改变，应保留预训练局部路径并以零初始化新增输入权重等方式构造行为等价的 warm start；另报同信息从头训练满预算版本，防止刻意选择弱初始化。所有此类设计在看筛选结果前锁定。

### 5.2 外部比较算法

现有11种方法继续保留：GC-MAPPO、MAPPO、IPPO、CoLight、PressLight、Max-Pressure、Fixed-Time、Double DQN、Dueling Double DQN、GAE Actor-Critic、REINFORCE。

分层运行，不把所有方法提前铺满全部试验：

- **核心性能比较：** IPPO、IPPO+、MAPPO、经验证的 CoLight/PressLight、Max-Pressure、Fixed-Time、至少一个近邻强方法及最终候选。
- **经典完整性比较：** Double DQN、Dueling Double DQN、GAE Actor-Critic、REINFORCE、旧 GC-MAPPO，可在主文或补充材料的锁定核心场景完整报告。
- **近期强方法：** 优先评估 SocialLight 或 CoordLight 的官方实现可运行性及与任务接口的匹配；并核对 CoSLight 与门控选择的关系。SocialLight摘要称其覆盖SUMO与CityFlow，但本轮未取得其代码或复现实验；CoordLight相关页面本轮未取得返回，不能据此写入CityFlow依赖或可运行性结论。[R4、R6] 先检查同平台适配成本，再锁定强参考。未成功完成适配/核验时，保留明确缺口，不以当前本地重实现代替官方性能。

近期方法至少一个进入同平台强比较，是本项目投稿准备门槛，不是任一期刊硬性规定。SocialLight摘要页面称其覆盖SUMO与CityFlow，但本轮未核验实现或可复现实验；其他近期方法仍须取得一手来源并完成平台适配。跨模拟器论文公布数值不能直接与本项目 SUMO 数值拼表比较。

### 5.3 两条公平轨道

**机制轨道：** B0–B4与A/B共用reward、决策时钟、动作约束与总交互预算。B0/B2仅使用局部输入，作为信息/容量对照；B1/B3/B4与A/B使用相同邻域信息集合，用于区分信息和架构收益。不能将全部组称为完全同输入；冻结方式、warm start及参数量差异逐组登记。

**竞争轨道：** 外部方法保留其合理原生状态和训练目标，在统一交通任务、传感预算、动作约束和评估指标下充分调参，用于回答是否优于强方法。必要适配逐项披露。

不能为了“公平”强行取消竞争方法本来的关键输入，也不能给新算法额外未来信息。若信息需求确实不同，分为同传感约束比较与原生配置比较，不能混用结论。

Fixed-Time 应在训练/验证需求上调周期、绿信比和偏移；不只用一个任意的默认轮转控制器代表优化后的固定配时。Max-Pressure 的压力定义、最小绿、黄灯和 tie-break 也应固定并记录。

### 6.4 泛化声明分级

- 同拓扑、未见需求，冻结模型：可称需求泛化。
- 新拓扑从头训练：称跨拓扑训练后表现或扩展性，不称零样本迁移。
- 新拓扑微调：明确数据预算，称迁移适应。
- 独立路口 actor 数量/维度改变：不能天然零样本应用。若想主张零样本拓扑泛化，必须另行设计共享、排列等变或拓扑无关策略；本轮不强行增加该目标。

## 七、指标体系与“综合最优”的操作定义

### 7.1 不再用任意等权排名定义成功

吞吐量、完成率、未完成率高度关联，不重复计分。采用“**需求服务门槛 + 主效率指标 + 最差场景约束 + 成本披露**”。

本方案将“综合最优”限定为：在预注册场景与方法集合内，满足服务门槛，主效率具有实际与统计优势，且没有预先规定的严重退化；不意味着每个指标、每个场景、所有可能算法都第一。

### 7.2 服务率与需求守恒

令 V 为在需求窗口内计划出发的车辆集合，N=|V|；使用固定需求窗口及预先确定的统一清空窗口，评价截止为 T。

- **需求完成率 C**：在 T 前正常到达、且未发生被排除的异常移除/teleport 的车辆数除以 N。
- **吞吐量**：对应正常完成车辆数，不独立重复加权。
- **未正常完成的分项**：分别报告尚未首次插入、仍在网、暂时离网等待重新插入、异常到达、取消/永久异常移除的车辆比例，分母均为N。与正常完成率相加必须等于1；取消/永久移除额外记录是否曾入网。
- **Teleport**：事件次数和受影响车辆数分别记录，不能通过允许更多 teleport 来提高表面吞吐量。

对于 flow 文件应保留实际实现的计划车辆序列/需求生成随机种子；不能简单以名义流率乘时间当作精确 N。需求窗口、边界时刻包含规则、清空窗口和异常车辆处理在筛选前固定。

### 7.3 主效率指标：有限时域需求服务耗时 U

为避免仅对完成车辆统计造成的选择偏差，建议主终点使用以下本项目预定义量：

\[
 U=\frac{1}{N}\sum_{v\in V}\left[\min(t_v^{normal-arrival},T)-t_v^{scheduled-departure}\right].
\]

未正常到达车辆令 `t_v^{normal-arrival}=+∞`，因此其耗时累计到 T；等待插入时间被计入。异常移除不视为正常到达。该量等于计划出发后尚未被正常服务完成车辆数随时间积分再除以 N。

**解释边界：** U是固定评价窗内的平均截断服务耗时，单位秒/计划车辆，不是完整行程平均旅行时间，也不声称无截尾偏差。所有方法必须使用相同需求、截止和异常规则；完成率门槛与残余未完成量同时报告。选择 U 是研究设计建议，P0完成后在任何候选性能筛选前正式锁定。

**主文同时报告标准指标，保证与文献沟通：** 已完成车辆平均旅行时间、departure delay、SUMO timeLoss、排队、P95行程耗时、等待时间、清空情况。已完成车辆指标明确带条件，不能单独支持总体优势。U与标准指标结论不一致时解释原因，不只展示有利指标。

### 7.4 初始实用门槛

以下数值是拟采用的工程决策默认值，非既有实验效应或期刊要求；需在候选结果可见前由负责人确认，可根据交通意义和测量精度调整一次并留痕。

| 维度 | 拟定门槛 | 解释 |
|---|---|---|
| 需求完成率非劣 | `C_new - C_ref > -0.005` 的单侧、家族校正置信下界成立 | 非劣界为0.5个百分点，不是0.5%相对值 |
| 汇总效率实际改善 | U相对降低的点估计至少3% | 仅统计显著但效应极小，不作为工程成功 |
| 汇总效率统计优势 | 同一相对改善量的家族校正单侧置信下界大于0 | 不显著不等于非劣或相等 |
| 关键场景效率退化 | 每个预指定关键场景，改善量置信下界高于−5% | 防止平均收益掩盖严重场景退化 |
| 异常交通行为 | 不靠teleport、跳过安全相位或异常删除车辆获得收益 | 异常全报告并分析 |
| 部署与训练成本 | 完整报告推断时延、参数量、总训练计算及通信量 | 是否实用取决于真实控制周期，不能仅以参数量代替 |

上述门槛先用于最终候选相对 IPPO、IPPO+ 和验证集锁定的最强外部学习基线。若要写“优于所有比较方法”，还必须将全部比较加入预注册推断家族并达到相应证据标准；否则只能写“优于指定关键基线/具有竞争力”。

## 八、统计方案与选模防泄漏

### 8.1 独立单位和配对

每个训练 seed 对应一个独立训练模型；其多个评估 seeds 是同一模型的重复测试，不是新增训练样本。先保存每个训练seed×评估需求/seed×场景的明细，再按预注册权重聚合。

- 同场景同评估需求对所有方法一致。
- BR、GR和IPPO-continue在机制轨道中共享同一训练seed的前半程checkpoint，因此有明确区组配对。
- 外部算法不能只因整数seed相同就宣称随机初始化高度配对；记录共同外生需求序列，说明区组定义。
- Fixed-Time/Max-Pressure没有训练随机性，不把复制出的10个目录当成10次独立训练。与学习方法比较时，在相同评估任务下构造每个已训练模型对固定控制参考的差值；结论条件于所用需求集。若推断到需求总体，应另处理需求层不确定性。

### 8.2 汇总和效应量

令 `U_mks` 为方法m、训练区组k、场景s上对评估任务平均后的U。使用 `log(U_ref/U_new)` 表示改善方向，先在场景内配对，再对预定义场景族等权聚合；用 `1-exp(-mean_log_ratio)` 换回相对降低比例。所有值必须为正且通过计数检查，不用任意epsilon修补零或错误值。

完成率报告百分点差。标准指标报告绝对差、相对差和区间；训练稳定性报告跨seed分布与失败率。原始轨迹可展示，但不能把每个时间步当成独立推断样本。

### 8.3 确认性推断

1. 初始计划以每个学习方法每个训练场景 **10个独立训练seeds** 为起点；在只使用发展数据的阶段，按效果门槛及方差估算所需精度，再锁定最终样本量。10不是自动充分。
2. 列清全部确认性假设，包括关键参考的汇总U优效、关键场景C非劣和退化约束，预先得到家族大小H。
3. 以训练区组为重采样单位估计差值区间，保留区组内跨场景、跨方法关联。默认采用适当的训练区组bootstrap区间，并以Bonferroni单侧尾概率 `0.05/H` 作家族校正；重采样次数须足以稳定估计该尾部，在发展阶段验证实现。
4. 该bootstrap推断是有限样本近似，不宣称精确有限样本保证；样本小、分布极偏、尾部不稳定时，增加预先确定的训练重复数或降低结论强度，不能只增加bootstrap次数冒充新增证据。
5. 若需要p值，另预注册有适用假设的检验；配对sign-flip只有在相应可交换/对称条件合理时才使用，并对对应家族执行Holm。不得把现有“bootstrap跨零比例”直接称作精确置换检验。
6. 主分析条件于固定的确认场景与评估任务集；对需求总体的推广另做分层或交叉重采样敏感性分析，保持所有方法的共同任务配对，不把交叉设计误作简单独立嵌套。
7. 补充报告逐训练seed散点、leave-one-seed-out稳定性和未校正区间，并明确它们是描述/敏感性结果，不能代替校正后的主要结论。
8. 所有失败、超时和NaN运行先分类：基础设施故障按固定规则同seed重跑并保留记录；算法不稳定/合法仿真中的死锁不得选择性剔除。不对失败结果任意填0。

强化学习少量运行的点估计容易误导，因此区间、完整分布和固定评价计划应与均值同等重要；这一原则有原始研究支持，但本文具体门槛和统计家族属于本项目设计。[R7]

### 8.4 候选和checkpoint选择

- 只使用发展/验证数据选择checkpoint和候选。
- 两候选使用相同预训练阶段长度、协同训练预算和验证频率。
- 先排除服务率明显不合格者，再按预定义汇总U选型；差异不足发展阶段预设的实用阈值时，优先计算更省、结构更简单者，不能凭个别场景选名次。
- 候选确定后，只保留一个最终模型家族进入主确认；另一候选可作为预注册消融，但不能在主候选失败后直接把确认集变成第二轮选型集。
- 确认失败后若修改方案，应建立V2和新的独立确认数据；不能继续用同一测试集反复“确认”。

### 8.5 发展阶段的可执行筛选规则（拟定，运行前批准）

以下是控制预算的启发式停走规则，不是统计显著性结论；小样本未通过不证明机制普遍无效。所有阈值只可在对应结果可见前调整并留痕。

- **P1通过：** 在预指定瓶颈发展场景族中，IPPO+相对IPPO的汇总U降低点估计达到3%，且3个训练区组至少2个改善；相对IPPO-Cap的汇总U也应改善。各关键场景完成率均值差不低于−0.5个百分点，普通需求场景U均值退化不超过5%。若仅容量对照同样获益，不认定信息价值已成立。
- **P2通过：** 至少一个候选相对IPPO+的汇总U降低点估计达到3%，且3个区组至少2个改善；相对IPPO同时满足服务率和效率筛选条件。关键场景采用相同服务率/退化门槛。还须通过初始化、冻结/梯度和动作概率一致性检查。
- **候选择优：** 在通过门槛者中选择汇总U更低者；两者U相对差距不足1%时，优先协同阶段实测训练计算更少者，再按推断时延、可训练参数量排序；仍相同则按预登记顺序BR优先。这是开发决策，不宣称BR理论上更稳。
- **门控/图创新保留：** 对匹配冻结方式的无门控/非图对照至少呈现方向一致的增益迹象，才保留对应创新主张；发展阶段不能据此宣布机制成立，仍需P4完整消融。
- **一次修正上限：** P1与P2合计最多一次证据驱动的重试回合，明确修改项、额外任务数及停止条件；不得在两个阶段分别无限刷新机会。预算不允许重试时直接暂停。

## 九、训练预算与逐级扩展

### 9.1 预算单位

训练预算至少同时记录：环境模拟秒数、控制决策次数、各路口有效决策数、优化更新次数、总样本数、CPU/GPU小时和峰值内存。不能仅以episode数表示所有网络规模与方法成本。

设公共交互预算 `B=B_pre+B_adapt`。BR/GR必须把预训练计入B；IPPO基线在同一B内继续训练。共享预训练checkpoint能减少本次研究的实际计算，但每个方法报告的学习预算仍包含其所依赖的预训练。

B_pre比例、B和验证频率用IPPO及简单控制组的发展曲线确定，并在双候选筛选前锁定。不得预设20或50轮必然收敛；如需扩大预算，应对可比方法一致扩大并保留原结果。

### 9.2 调参边界

- 首轮只探索协同强度c与协同学习率等少数关键量；具体候选集合在发展实验前登记。
- 不同时搜索图深度、reward、时长、critic、Q head及初始化。
- 每方法登记最大配置数、每配置训练预算、早停规则及最终选择标准。资源上限由P0短运行实测后确定，不能当前凭空给出GPU小时。
- 强基线给予事先分配、可说明的调优预算；若新方法使用大量探索，应披露全部开销，而非只报告最优运行。
- P1与P2合计共享一次有明确诊断依据的修改回合（见8.5节），不是每阶段各一次。额度已用、缺少诊断依据或重试仍不通过时，暂停该路线，不滚动扩大搜索；另立方向须获得新的证据与批准。

## 十一、消融、机制诊断与失败处理

### 11.1 必做消融

1. 去掉新增邻域信息：信息增益。
2. 相同信息直接拼接：架构增益。
3. gate固定为1：选择性必要性。
4. 去掉/替换图聚合：图结构必要性。
5. 冻结与联合训练：底座适应性的作用。
6. 去掉下游接纳代理特征但保持其余信息：物理瓶颈信息作用。
7. 至少一个近似匹配参数量对照：额外容量作用。

不要求每项都成为性能提升；没有作用的模块原则上删除。若删模块发生在确认后，删除后的算法是新版本，需要明确重新验证哪些主张。

### 11.2 机制证据不只画注意力图

预先定义瓶颈事件，例如下游占用持续越过发展阶段选定阈值；阈值不根据候选胜负反调。报告：门控值、残差范数、动作改动率、相位切换率、下游阻塞持续时间、方向性队列和服务率。

将数据按预定义的有/无瓶颈状态分组，分析收益是否符合机制预期。注意力/gate与拥堵相关只是关联，不是因果证明；必须结合去特征、无门控及同状态扰动等消融。

受控瓶颈场景要与普通场景共同报告，不以人为制造唯一有利场景替代一般性评价。

### 11.3 通信与稳健性

在同一冻结checkpoint上测试预登记的消息丢失、一个或多个控制步延迟、测量噪声。所有通信型对照接受相同扰动；无通信方法作为参照。报告消息有效性处理和通信负载，不将“带通信执行”称为“零通信分散执行”。

只有实现并测量了门控前抑制消息发送，才能主张降低通信量；计算完所有邻居消息再乘gate，不自动节省通信或图编码成本。

### 11.4 失败决策表

| 观察结果 | 解释边界 | 下一步 |
|---|---|---|
| IPPO+不优于IPPO | 新信息/环境条件可能不支持当前假设 | 仅在P1/P2共享的一次修正额度尚未使用时，检查特征、可观测性与瓶颈；无依据或额度已用则暂停该方向 |
| BR/GR优于IPPO但不优于IPPO+ | 主要可能是观测升级，不支持残差机制优势 | 简化结构；不能仍包装为门控图残差创新 |
| 无门控版本相同或更好 | gate必要性未成立 | 删除gate或退出该创新点 |
| BR优于GR且GR退化 | 联合更新可能损害局部控制，但尚需诊断 | 优先BR，保留GR失败为消融，不继续堆critic |
| GR优于BR | 冻结可能限制适应 | 选择GR，明确没有原始底座回退保证 |
| 只在一个瓶颈场景有效 | 研究可能是条件性优势 | 明确作用域，补普适场景；不得称全局综合最优 |
| 服务率下降但完成车辆延误更低 | 可能存在选择偏差或吞吐量牺牲 | 按门槛判失败，不用延误改善掩盖 |
| 确认区间很宽 | 证据不足而非自动无效/有效 | 按预注册精度设计处理，不事后加seed直到显著 |
| 最近文献已有相同机制 | 新颖性不足 | 重定义有实质区别的问题，暂停确认扩展 |
| 两个候选均无优势 | 当前路线未实现总体目标 | 停止本路线，保留证据；只有新证据支持才另立方向 |

暂不把预测增强IPPO和邻域critic作为自动启动的第三、第四候选。双候选是降低单一训练策略风险，不是两条相互独立、足以保证成功的科学路线。

5. **实验协议：** 公开数据来源、划分、基线适配、调参预算、独立seed、主终点及家族校正。
6. **结果：** 完整性能与不确定性、消融、机制、OOD/规模/成本及失败案例。
7. **讨论与局限：** 观测可得性、独立actor迁移限制、通信需求、真实部署缺口、未通过场景。
8. **结论：** 只陈述得到支持的范围和未来工作，不把局部结果外推成所有城市有效。
